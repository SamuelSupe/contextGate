# 查询复用试点工作表

[English](query-pilot.md) · [查询发布](query-publishing.zh-CN.md)

这是采集模板，不是效果报告。先确认配置维护人、业务评审人、现有 Agent 工作流和固定样本/数据版本。缺失项标记缺失，不把人工估计当服务端测量。

| 尝试 | 来源/模板/版本 | 开始至首次匹配客户端调用 | 人工操作分钟 | 完成/放弃/失败 | 阻塞与请求 ID |
| --- | --- | --- | --- | --- | --- |
| 每次有效尝试都填写，包含失败 | | | | | |

至少观察十次有效配置尝试，再计算完成率与激活时间中位数。分母包括所有有效尝试；后续查询上线耗时单列。记录开始时凭证、可运行查询与客户端是否已准备好，区分等待时间和人工操作时间。

收集 30 个**真实**试点问题：20 个用于改进，10 个保留为独立验收，条件允许时每题运行三次。覆盖同义表达、时间/退款边界、空结果、未覆盖问题、歧义和越权身份。示例问题不等于真实样本；敏感参数、标准答案和验收机密不应放进公开语义描述。

| --- | --- | --- | --- | --- | --- | --- |
| | | | | | | |

复用现有“单次答案”和可选对照评估。人工结论归属于相应运行与配置。所谓原生基线必须真的使用原生查询；调用了模板就据实标注。模式或目录不同的两组应使用等价权限的隔离配置，不关闭配置变化提示。查询执行耗时不等于端到端回答时间，也不是数据新鲜度。

正确、部分正确、错误、未评审、失败和未完成分别报告。正确率分母为已完成且已评审运行；评审覆盖率分母为全部有效发起运行。报告分母与样本量，不把成功调用审计当作全部业务问题。

至少两个真实 Agent 持续使用才能报告跨 Agent 复用，排除测试客户端和预览。连续两周净收益为正是试点决策条件，不是当前产品成绩。费用仅在客户端有可信 usage 时记录，否则标记缺失。负责人字段、周期回归、目录集成和检索排序应依据实际阻塞再决定，不默认全部扩建。
