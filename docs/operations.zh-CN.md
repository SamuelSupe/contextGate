# 运维与安全变更

[English](operations.md)

本文对应当前源码；运行旧版本时请查看对应发布标签中的文档。内建元数据使用 PostgreSQL，加密密钥独立保存。设置页与 `contextgate version` 显示构建提交；包含 Go VCS 信息的本地构建还会标记未提交修改。

## 发布前审核

“数据源 → 语义 → 审阅并发布”集中显示验证状态、条目变更、显式关联查询及当前 Agent 授权。可以直接执行缺失的模板试跑（示例及全部已配置回归用例）或映射检查。失败、过期的验证会阻止发布，提交时再次检查草稿修订和证据；发生并发修改时需要重新加载审核。

审核区分业务说明变化与查询执行变化。纯说明修改保持执行版本，不取消运行中的查询；查询定义变化或重新验证发布时沿用原有版本及取消规则。影响关系来自显式目录和本体引用，不解析原生查询推断完整依赖。列出的 Agent 具有有效数据源授权，不代表实际使用过某个模板。

修改数据源连接、凭证、启停或查询模式时，编辑器会在保存前提示实时影响。连接变化使模板验证失效；名称、说明及查询上限修改不使其失效，查询仍遵守最新上限。

## 管理员职责

所有管理员共享业务配置。超级管理员还可管理账号、全局设置、健康检查策略及 OTLP。账号、密码和个人配置 MCP Token 事件进入受限的“账号安全”审计分类。新增账号、个人 Token 和升级说明见[管理员指南](administrators.zh-CN.md)。

## 聚焦审计活动

“审计日志”默认显示“真实 Agent 调用”。“人工预览”包括管理员及所选 Agent 身份预览；“系统检查”显示新记录的定期或手动健康结构检查；“全部活动”也包含管理变更。可继续按管理员、配置身份、调用入口、数据源、调用者、结果及时间筛选。账号安全事件仅超级管理员可见。健康检查不会完成 Agent 接入验证。

系统结构检查使用 `event_kind=system`，通过已有 OTLP Logs 属性一并上报。新分类仅适用于新记录，历史记录保留原始分类。审计内容及保留策略不变，不新增查询文本或结果记录。

## 变更追溯与版本恢复

在“审计日志 → 事件类型 → 管理变更”查看数据源配置、查询 Agent 授权及凭证、本体与语义编辑/发布、OAuth 客户端管理及运维设置。记录管理员、资源 ID、操作、修订、提交的字段类别、时间与结果。字段类别表示请求提交了哪些字段，不是字段值差异。不保存查询、业务定义、参数值、密码或结果，沿用 30 天保留期和 OTLP Logs 上报。

变更前先持久化操作意图；记录失败时拒绝变更。随后另记成功或失败结果。界面在有结果后隐藏对应意图，OTLP 上报两条具有相同 request ID 的事件。崩溃或结果写入失败时保留“结果待确认”，不会伪报成功。重试前先核实当前配置，健康页会提示超过三分钟仍没有结果的操作。

“数据源 → 语义 → 发布历史”保留加密的不可变快照。选择历史版本可查看条目、原生查询和回归约束与当前草稿的差异。“恢复为草稿”需要确认并校验修订，仅替换草稿，不切换当前发布内容。启用模板必须再次试跑，本体映射必须重新检查，随后才能发布。Agent 在此期间继续使用原发布版本。

恢复后执行定义未变时保留执行版本；查询变化时继续按原有规则取消任务和拒绝旧游标。历史快照保护引用的本体版本，防止恢复时定义缺失。可显式删除不再需要的历史快照以释放引用，但不能删除当前发布版本。删除数据源时原子清理其历史。旧存储升级只能保留当时的当前发布内容，标为“升级时保留”，无法重建更早历史。

## 健康检查

“健康状态”集中显示连接证据、已发布对象结构变化、模板验证失效、七天内到期或已过期的凭证及 OTLP 上报错误。“刷新”读取已存证据，“立即检查”才执行真实只读检查。只有超级管理员可配置定期检查；默认关闭，间隔可设为 5–1440 分钟，在后台工作器下一个一分钟检查点到期执行。

检查逐源串行执行，遵守查询上限，每源最多 30 秒。除连接探测外，比较最多 20 个已发布对象引用（含本体映射）的可发现字段名与原生类型，不执行模板、不读取业务样本、不枚举整个数据库。Redis/Valkey、Neo4j、InfluxDB 的字段发现可能读取数据，因此后台不执行，显示未验证。MongoDB 证据只覆盖索引字段。界面显示覆盖范围及检查时间；配置变化后证据失效，定期检查逾期也会标注。

发现数据库版本变化会沿用现有机制使模板连接验证过期。结构差异持续显示，直到管理员确认“接受新基准”；接受基准不等于重新验证模板、映射或权限。未纳入已发布引用的对象不受监测。权限检查只报告实际只读证据，不发送试探性写入。

## 模板回归检查

编辑模板中的“回归检查”，最多添加十组命名用例：

- `parameters_json`：通过原有参数契约绑定的 JSON 对象。
- `min_rows` / `max_rows`：可选的闭区间行数约束，范围 0–10000；均为零表示预期空结果。
- `columns`：预期列名及可选的精确原生类型。
- `values`：在 `result.data` 中使用 JSON Pointer 指定精确 JSON 预期。表格行是数组，如 `/0/0`；文档保留字段，如 `/0/total`。大整数和 Decimal 使用返回结果的无损编码。字符串与数值不同，数值文本也精确比较。

一次试跑执行示例和所有回归用例，共享当前模板超时。“运行全部模板检查”共享 120 秒预算，并报告尚未执行的模板。失败会阻止草稿发布，当前已发布模板继续可用。试跑丢弃结果，仅将用例名称、状态码、数量与耗时保存在加密验证证据中。用例参数和预期值仅管理员可见，不返回给 Agent。

回归约束变化要求重新试跑，但不改变原生查询执行版本，也不取消运行中的调用。截断或仍带分页游标的结果不能通过回归检查，请用范围明确的查询验证完整结果。该机制验证管理员指定的预期，不进行模型评分或自动业务推断。发布历史包含回归契约差异。

## PG 诊断与备份恢复

主密钥目录必须使用持久化存储，不要放在 `/tmp` 或重启时会清理的目录中。恢复需要 PostgreSQL 元数据和匹配的 `master.key`；生成新密钥无法解密现有记录。

超级管理员可在“设置 → 部署诊断”只读检查 PG 连通性、实际版本与 TLS 传输、密钥匹配、元数据结构和连接池。可复制的报告不含地址、凭证、源名称或查询数据。密钥匹配不代表已备份密钥，TLS 传输也不证明证书校验策略正确。PG 不可用时管理登录也可能不可用，此时检查 `/healthz`、容器状态和启动日志。

使用项目 Compose 部署时，在部署目录执行：

```sh
bash scripts/backup-metadata.sh /secure/backups/hub-20260914
MCPDBHUB_VERIFY_IMAGE=contextgate:local bash scripts/verify-backup.sh /secure/backups/hub-20260914
```

目标目录必须不存在。备份包括一致的 custom 格式 `pg_dump`、匹配的 32 字节密钥（支持环境变量密钥）、构建信息和校验和。失败的备份没有有效最终校验清单。备份可恢复凭证，应放在受限、加密的存储中。额外保护部署 `.env` 及配置，重启时不要重新生成数据库密码。脚本不备份外部数据库或作为数据源的 SQLite/DuckDB 文件。备份期间不要轮换密钥或改连接。`pg_dump` 客户端版本不能低于服务器，默认 PG 镜像为 17.11。

回验先检查清单，再恢复到专属内部网络中的新临时 PG 容器，使用匹配的 ContextGate 镜像执行 `verify-metadata`。该命令通过只读事务校验密钥、逐条解密元数据、检查 JSON 并统计记录，不初始化或迁移库、不启动服务或上报器、不连接数据源。脚本只清理本次创建的临时容器和网络。成功 JSON 报告明确 `source_connections_opened: 0`。可用 `MCPDBHUB_PG_IMAGE` 指定兼容的恢复镜像。只验证可信管理员备份，PG dump 属于可信部署制品。

真实恢复时先停 ContextGate，在**新建空数据库**执行 `pg_restore --exit-on-error --no-owner --no-acl`，恢复匹配的 `master.key` 或 `MCPDBHUB_MASTER_KEY`，调整 `MCPDBHUB_DATABASE_URL` 后启动匹配构建。密钥文件权限设为 0600，恢复服务用户所需所有权；确认恢复前保留旧数据库。备份也恢复当时的会话、Agent/OAuth 授权及上报进度，因此重新暴露服务前需核对备份后的撤销操作与 OTLP 发送情况。最后登录、运行诊断，并实际验证所选源连接及 Agent 授权。

服务不监控备份的新鲜度，请将实际回验输出保存到部署记录中。部署诊断通过不等于完成恢复演练。

结构差异每个对象最多显示 10 个新增、删除或类型变化字段，证据过大或无法获取时明确显示详情受限。元数据应使用独立的 PostgreSQL 数据库，`pg_dump` 会备份所配置的整个数据库。
