# ContextGate 0.8.1

**Faster initial loading and bounded audit maintenance.**

[简体中文](0.8.1.zh-CN.md) · [Installation](../install.md) · [Operations](../operations.md)

## Fixes

- Load management pages, source editing and settings panels on demand. The production entry JavaScript decreased from 770.40 kB to 426.66 kB (uncompressed); this is a bundle measurement, not a browser latency guarantee. Shared styles remain available on direct page visits.
- Retain visited settings forms and protect unsaved edits, in-progress operations and one-time credentials when switching sections. Audit status polling stops while its panel or browser page is hidden; server-side delivery continues.
- Revalidate embedded HTML, cache content-hashed assets and return uncached 404 responses for missing assets. Deferred-page failures offer an explicit reload action that respects unsaved changes.
- Bound audit writes, including connection-pool and lock waits, with an independent ten-second budget. Synchronous persistence, failure behavior and commit-order protection for export cursors remain intact.
- Delete expired audit records in batches of at most 1,000 within a one-minute hourly cleanup budget. The 30-day retention boundary is unchanged; incomplete cleanup is logged and retried next hour.
- Separate login, settings, connector catalog and OAuth consent components, and reuse display labels independently of page modules.

## Compatibility and upgrade

From **0.6.x, 0.7.x or 0.8.0**, back up the PostgreSQL metadata database, matching master key and deployment configuration. Stop ContextGate, replace the complete archive or image with 0.8.1, then restart with the same database URL, key and source-file directories. Verify a known query and audit record afterward. No metadata migration or forced credential rotation is introduced.

Audit persistence exceeding its budget returns an audit failure; a successful query result still requires its audit record to commit. Existing `elapsed_ms` excludes the final audit write, so use client-side timing for end-to-end latency. This release does not claim increased sustained audit throughput.

For older installations, follow the [installation upgrade guidance](../install.md). Existing routes, query/Configuration MCP tools and publication contracts remain compatible.

## Packages and verification

Download `contextgate-0.8.1-linux-arm64.tar.gz` or `contextgate-0.8.1-linux-amd64.tar.gz` and verify `SHA256SUMS`. Keep the launcher, `libexec` and private C++ libraries together. Linux glibc 2.36+ and PostgreSQL metadata are required; Node.js is not required at runtime. The `mcpdbhub` launcher remains available.

The [release assets](https://github.com/SamuelSupe/contextGate/releases/tag/v0.8.1) carry `release-verification.json`, `dist-arm64.json`, `dist-amd64.json`, `download-arm64.json` and `download-amd64.json`. Consult these records for the exact source commit, native dual-architecture CI, archive hashes and actual package/download checks. Local amd64 package execution uses OrbStack emulation on an arm64 host.

Package checks cover PostgreSQL and HTTP API queries, HTTP/stdio MCP, templates and ontology context, administrator recovery, restart persistence, revocation and OTLP HTTP/protobuf and gRPC. The full external database matrix remains historical evidence; this maintenance release does not claim a new full-matrix run, long-duration load test or real cloud-warehouse validation. See [validation](../validation.md).
