# ContextGate 0.6.0

**Named administrators, personal Configuration MCP identities, and Apache-2.0.**

[简体中文](0.6.0.zh-CN.md) · [Administrator guide](../administrators.md) · [Installation](../install.md)

## What's new

- **Administrator accounts:** sign in with a username and password. Super administrators manage accounts, roles and global settings; administrators share sources, semantic catalogs, ontologies, query Agents and OAuth clients. New accounts receive a one-time temporary password, valid for 24 hours, and must change it before accessing business configuration.
- **Personal Configuration MCP:** each account owns one stable configuration identity with at most one active token. Owners issue, rotate or revoke their own token. A super administrator can revoke another person's token, but cannot issue or retrieve it for them.
- **Targeted access revocation:** disabling an account, changing its role or resetting its password invalidates that person's sessions and configuration token and cancels their running configuration work. Changing your own password retains this session and your configuration token. Query Agent credentials and OAuth grants remain independent.
- **Attributable audit:** UI changes, Configuration MCP, connection checks, template trials and Agent previews retain the actual administrator and execution identity. Filter by administrator, configuration identity, entry point and result. Account security events are visible only to super administrators. OTLP HTTP/protobuf and gRPC include the new identity fields without credentials, parameters or results.
- **Apache-2.0:** ContextGate now uses the Apache License, Version 2.0. Source, Docker images and Linux distributions include LICENSE and NOTICE. Third-party components retain their own licenses and notices.

English remains the default UI and documentation language; Simplified Chinese is available in Settings. Business configuration remains shared across administrators; this release does not introduce resource ownership, tenant isolation or teams.

## Upgrade from 0.5.x

1. Back up the PostgreSQL metadata database, matching master key and deployment configuration using the [backup guide](../operations.md#back-up-and-verify-recovery).
2. Stop the previous service. Replace its package or image with 0.6.0, preserving the database URL, master key, data directories and public URL. Do not run old and new versions against the same metadata database.
3. Start 0.6.0. The migration creates the initial super administrator with username **`admin`** and retains the **existing password**. Old browser sessions are invalidated; sign in again.
4. **All old Configuration MCP tokens are revoked.** Create administrator accounts for the owners, then have each owner issue a personal token in **Settings → My configuration MCP** and update their clients.
5. Verify account roles, a real query Agent call and the audit entry for a configuration operation.

Data sources, encrypted credentials, semantics, ontology versions, query Agent/OAuth grants, evaluations and audit history remain intact. Historical identities are not attributed retroactively to a specific person. Account migration is transactional and idempotent. Application rollback requires restoring the pre-upgrade database backup and its matching key.

For CLI password recovery, specify `--username`; omission is allowed only when exactly one account exists. Recovery preserves that account's role and enabled state and does not revoke other administrators' access. See [recovery instructions](../administrators.md#recover-a-forgotten-password). The executable alias `mcpdbhub`, `MCPDBHUB_*` settings and existing query MCP contracts remain supported.

## Packages and verification

Download `contextgate-0.6.0-linux-arm64.tar.gz` or `contextgate-0.6.0-linux-amd64.tar.gz`, verify `SHA256SUMS`, and follow the [installation guide](../install.md). Archives include the embedded UI, private C++ runtime libraries, English/Chinese help, examples, LICENSE, NOTICE and dependency notices. Linux glibc 2.36+ and PostgreSQL metadata are required; Node.js is not needed at runtime.

Release attachments identify the exact source commit, native amd64/arm64 CI and archive/download checks. The package workflow exercises HTTP/stdio queries, configuration MCP, HTTP API templates, upgrade-related password recovery and both OTLP transports with two administrators. Local amd64 archive execution uses OrbStack emulation. The 18-product / 20-version database matrix and Chrome workflow records retain the exact implementation and test-stage scope in [validation](../validation.md).
