# ContextGate 0.5.0

**HTTP APIs, a business query catalog, and simpler Agent workflows.**

[简体中文](0.5.0.zh-CN.md) · [Getting started](../getting-started.md) · [Installation](../install.md)

## What's new

- **HTTP API data sources:** configure fixed GET or POST JSON operations, authentication, scalar parameters, response fields and token pagination. Agents use `query_http_api` or published templates without supplying URLs, headers or request fragments. Configuration MCP, source grants, semantics, ontology mappings and sanitized OTLP audit logs apply to these sources too.
- **Business catalog:** start with executable queries, expand to all published definitions, inspect source-authorized concepts and preview linked templates without losing the business context.
- **Guided authoring:** edit native query text, discover permitted existing parameter positions, generate templates from configured API operations, and focus ontology mappings on one entity with metadata field selection.
- **Single-answer evaluation:** capture a real client's calls, review its answer against your criteria, and retain a separate completion/review history. Baseline-versus-guided comparison remains available.
- **Clearer administration:** source-aware Home steps, publication review and change impact, separate client/preview/system audit views, credential-expiry links, settings sections, bilingual fixes and improved keyboard/narrow-screen interaction.

## Read-only and authorization boundaries

An HTTP operation's read-only behavior is declared by the administrator. ContextGate enforces its fixed request contract; it cannot prove that an arbitrary upstream API has no side effects or that its credentials are read-scoped. Connection success and permission evidence stay separate. HTTP mapping fields are declared metadata and remain unverified. See the [HTTP API guide](../http-api.md) and [runnable example](../../examples/http-api/).

The database support matrix remains 18 products / 20 version combinations. HTTP APIs are an additional source type. Query access still follows Agent → Data source grants, native/template execution limits and read-only validation; this release adds no federation, ontology instance store or inference engine.

## Upgrade from 0.4.x

1. Back up the PostgreSQL metadata database, its matching master key and your deployment configuration. Use the [backup and recovery guide](../operations.md#back-up-and-verify-recovery).
2. Stop the old ContextGate service and replace its binary/package or image with 0.5.0. Preserve the existing `MCPDBHUB_DATABASE_URL`, key directory, master key, database-file directory and public URL. Keep key storage outside temporary directories.
3. Start the new service. Existing sources, grants, semantic publications and template evidence remain in PostgreSQL. Previous evaluations retain their comparison mode; newly created evaluations default to a single answer check in the UI.
4. Check diagnostics, selected source connections and a real Agent query. Refresh clients' MCP tool discovery to expose `query_http_api`.

The `contextgate` command, `mcpdbhub` alias, `MCPDBHUB_*` configuration variables and existing MCP inputs remain supported. Versions through 0.3.x use a different metadata backend; follow the [earlier storage migration instructions](0.4.0.md#upgrading-from-03x-or-earlier) first.

## Packages and verification

Download `contextgate-0.5.0-linux-arm64.tar.gz` or `contextgate-0.5.0-linux-amd64.tar.gz` and verify `SHA256SUMS`. Packages include the embedded UI, private C++ runtime libraries, English/Chinese documentation, HTTP API and ontology examples, and dependency notices. Linux glibc 2.36+ and a PostgreSQL metadata database are required; no Node.js runtime is needed.

The Release attachments record native amd64/arm64 CI, the implementation-bound OrbStack database matrix, and actual archive/download checks. Local amd64 archive execution uses OrbStack emulation. HTTP API tests use isolated fixtures; their results do not certify arbitrary third-party APIs. [Validation details](../validation.md) distinguish the current gates from historical workflow evidence.
