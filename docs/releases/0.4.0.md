# ContextGate 0.4.0

**Semantic Data Gateway for AI Agents** — the first release under the ContextGate name.

The repository is now [SamuelSupe/contextGate](https://github.com/SamuelSupe/contextGate). Commit history and previous MCP DB Hub releases are retained. The default README, documentation hub, release notes and product presentation are English; the administration UI and usage guides also support Simplified Chinese.

## Highlights

- **Configuration MCP:** 22 typed tools at `/mcp/config` let trusted Agents prepare database connections, semantic catalogs, verified templates, ontology definitions and mappings. Dedicated short-lived credentials are separate from query access. Administrators review and publish drafts.
- **Graphical ontology editing:** edit entities, properties and relationships through graph and list modes, with contextual drawers, clearer selection controls, inherited definitions and source/template usage.
- **Guided Agent workflows:** source readiness, client configuration, lossless parameter forms, query previews and persistent question/evaluation history.
- **Operational controls:** management audit events, OTLP Logs, semantic publication history, restore-to-draft, optional health checks, regression trials, deployment diagnostics and backup verification.
- **PostgreSQL metadata:** configuration, sessions, grants, semantics and audit storage now use PostgreSQL. Credentials and definitions remain encrypted with an independently stored master key.
- **Read-only hardening:** nested MySQL locking reads are rejected; OAuth request bodies no longer hold shared mutation locks; administrator password changes revoke sessions atomically.

## Install

Download `contextgate-0.4.0-linux-arm64.tar.gz` or `contextgate-0.4.0-linux-amd64.tar.gz`, verify it with `SHA256SUMS`, and follow the bundled [installation guide](../install.md). Packages include the executable, embedded UI, private C++ runtime libraries, English/Chinese help, examples and dependency notices.

Linux packages require **glibc 2.36 or newer**. They require a pre-created PostgreSQL metadata database. macOS and Windows users can build and run the included Docker Compose deployment. No native macOS/Windows or Alpine/musl archive is provided.

## Upgrading from 0.3.x or earlier

This release intentionally provides **no SQLite metadata import or compatibility backend**. It is a new configuration store, not an in-place conversion.

1. Stop the old service and back up its metadata and matching master key. Retain the old executable and deployment configuration for rollback.
2. Prepare a fresh PostgreSQL database and a dedicated owner role. Configure `MCPDBHUB_DATABASE_URL`; use a new key directory for a fresh installation.
3. Start 0.4.0, initialize the administrator, recreate sources and credentials, and recreate Agent grants. Semantic/ontology JSON exports can be reviewed and imported as drafts; repair references and rerun validation/trials before publication.
4. Copy new client credentials and verify real Agent calls before switching users to the new deployment. Old query tokens and OAuth sessions do not move into the fresh store.
5. Retain the old backup until the new deployment is accepted. Rollback uses the old executable and its matching metadata/key backup.

SQLite remains a supported **query data source**. Existing development deployments already using PostgreSQL should instead back up their PostgreSQL database and key, then start the new executable against those same resources. Use the [operations guide](../operations.md) for recovery verification.

The primary command is `contextgate`; the `mcpdbhub` alias, `MCPDBHUB_*` environment keys and existing telemetry attribute names are retained. Keep the complete extracted distribution together. Update Git remotes to `https://github.com/SamuelSupe/contextGate.git`; the Go module now uses that path.

## Verification and scope

Release assets include source-bound archive validation reports. CI runs the Go suite and race checks on native Linux arm64 and amd64 runners. Local archive acceptance uses OrbStack, with amd64 execution emulated on the arm64 host. The database matrix uses isolated Linux arm64 fixtures; those results do not establish every database/version on both architectures.

See [validation](../validation.md), the [support matrix](../support-matrix.md), and the reports attached to the release for actual results. ContextGate remains single-instance and single-administrator. Ontologies describe business concepts; this release does not add graph instance storage, reasoning or cross-database query compilation.
