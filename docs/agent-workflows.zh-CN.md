# 从数据库连接到有效的 Agent 查询

[English](agent-workflows.md)

从 **首页 → 新建查询** 开始连续流程，或从首页继续已保存配置。具体模板的调用证据按来源、模板执行版本和 Agent 区分，时间窗口为 30 天；源级历史调用不代表所有模板已接入。详见[查询发布与恢复](query-publishing.zh-CN.md)。

## Agent setup

**Data sources** 中点击数据源名称进入查询工作台或 **Agent setup**。名称下方显示下一步、可执行模板与有效 Agent 数量。管理员结构探索位于 **More actions → Structure & native preview**。配置流程如下：

1. 检测连接并查看只读保护证据。连通、引擎保护、账号权限及查询 API 隔离分别展示，不发送试探性写入。
2. 在查询区上方选择具有当前数据源授权的有效 Agent，并打开真实客户端接入说明。新建 Agent 时预选当前数据源，仍需明确保存授权并保存新 Token。
3. 准备允许执行的查询，以所选 Agent 身份预览。原生模式支持原生预览或模板；仅模板模式需要可执行的已发布模板。连接变更后，重新试跑成功仍需发布才能恢复执行。
4. 在真实 MCP 客户端完成查询后刷新。只将当前源成功的非预览查询作为证据，结构发现和管理员预览不计入；历史成功不代表当前凭证和连接仍有效。

就绪页展示带时间的配置快照与历史证据，执行时仍由原有引擎重新校验权限、模式、限制和模板证据。Agent 接入面板解释常见错误，并提供进入模板或数据源配置的操作。`templates_only` 应通过 `search_semantics` 查找模板，再以当前执行版本调用 `execute_query_template`。

具备连接、授权、可用查询和真实客户端调用证据后，页面转为 **Query workspace**。已完成的配置项默认折叠，查询区保持展开；预览前明确展示所选 Agent。展开已完成项仍可查看证据或修改配置。

## 从业务概念找到查询路径

在 **Ontologies → Model**，实体卡片展示已发布映射的数据源数量和当前可执行模板数量。点击 **Queries →** 直接查看 **Queries and sources**，通过 **Definition** 切回定义；详情面板标题固定显示实体名称。列表模式提供相同入口。选择采用该本体的数据源，可看到固定本体版本、源发布版本、物理对象、映射属性、通过概念引用或映射明确关联的模板，以及当前有授权的有效 Agent。

点击 **Preview as Agent** 进入真实模板预览并保留所选身份。展示依据该源的已发布映射及固定版本，不自动使用共享本体最新版本。未映射的实体明确标记为对该源 Agent 不可见。这些管理页面仅供管理员使用，不向 Agent Token 开放。

## 验证业务问题的效果

从数据源配置或查询工作台打开 **Evaluate**。默认使用 **Single answer check（单次回答检查）**，采集一次真实客户端调用并人工评审；**Compare baseline and semantic guidance（对比基线与语义引导）**是可选的双轮模式。两种模式都不内嵌模型或自动评分：

1. 选择专用 Agent，避免同时运行其他请求；记录问题名称、模型、客户端设置、业务问题和答案验收标准。点击 **Save question for reuse** 保存到 **Saved questions**，也可直接开始临时评估。各模式提供可复制的提示词，验收标准不放入提示词，以免将预期答案提前提供给客户端。
2. 单次回答检查中启动采集，在真实客户端向所选 Agent 提问；等待所有调用结束，再收集指标。
3. 需要对照时，在开始前选择双轮模式：先用原有流程采集 Baseline，再在独立会话中以相同模型和数据采集 With semantic guidance，要求发现语义并适当使用已验证模板。
4. 人工评定答案为正确、部分正确或错误，记录原因并点击 **Save review**。采集自动保存；人工编辑未保存时阻止直接离开。通过 **History** 恢复采集、查看历史或重复评估，需要携带副本时导出 JSON。

问题和评估加密存储在 ContextGate 配置数据库中。采集时间、指标及配置快照由服务端生成；修改或删除问题不会改写旧评估。采集完成后的指标不受审计日志保留期影响。服务重启后可通过 History 恢复进行中的采集；过期后先放弃，再重新评估。并发编辑返回冲突，保留本地内容，允许另存新问题或明确丢弃后重载。

列表每页 20 条。每个源最多保存 1,000 个问题及 10,000 次评估，达到上限后需导出并删除旧记录，不自动清理。删除数据源时一并删除其问题和评估历史。备份需要同时保留配置数据库及主密钥。这些接口复用管理员会话与 CSRF 保护，不通过 MCP 暴露评估内容。

系统自动统计当前 Agent、当前源的已完成审计调用、查询、成功查询、错误、模板调用及 ContextGate 调用耗时之和；使用服务端时间，最长采集窗口 24 小时，排除管理员预览。没有源级审计记录的发现操作不进入计数，因此它不是全部 MCP 调用总数。耗时之和不是端到端回答时间，也可能包含并发重叠。

正确性由人工评审；系统不接入额外模型，不观察模型推理或 Token 消耗。工作表不会隐藏工具或更改权限。系统在开始时记录配置版本，并在收集后重新检查；单轮期间或两轮之间的配置版本变化会提示不可直接对照。评估期间应保持权限、数据、连接与定义稳定。收集前必须等待调用完成，未完成调用尚未写入审计。

导出包含问题、验收标准、人工备注、配置元数据和聚合指标，不自动保存查询文本、参数、结果或凭证。分享前请检查自行填写的业务信息。

建议用退款口径、客户身份及时间窗口等真实问题，多次测试后再判断语义带来的改善。SQL 执行成功并不证明业务答案正确。

## 客户端接入与参数表单

**Agents → Connect** 可选择 Codex、Cursor 或 VS Code，展示对应配置文件／命令、可复制配置及检查步骤。HTTP 配置引用客户端启动环境中的 `MCPDBHUB_TOKEN`，不把凭证嵌入配置示例；修改环境后需重启客户端，其他终端的 export 不会更新已启动的桌面应用。OAuth 配置使用浏览器同意流程；stdio 桥接保留在 Advanced 中。远程客户端应使用 ContextGate 已配置的公开 HTTPS 地址，localhost 指向客户端所在机器。

配置格式依据 [Codex](https://developers.openai.com/codex/mcp)、[Cursor](https://cursor.com/docs/context/mcp)、[VS Code](https://code.visualstudio.com/docs/agents/reference/mcp-configuration) 官方文档核对，不代表已认证每个客户端版本。真实连接仍需由客户端查询与审计记录验证。

模板预览默认按参数契约生成表单，支持必填、默认值、枚举、布尔、空值及精确数值范围检查；原生对象／数组参数仍使用 JSON 输入。可选参数可以省略，**Override default** 显式覆盖服务端默认值，**Use example values** 恢复示例。**Edit JSON** 保留完整参数对象，不会静默丢弃未知参数或重复键。大整数、Decimal 保留原始 JSON 数字文本，不通过 JavaScript Number 重写。

修改身份或参数后清空旧结果与游标；SQL/CQL 默认表格，文档和图数据默认 JSON，两种视图均可切换。空查询成功与执行失败分别提示。服务端仍负责最终的授权、参数绑定、只读和限制检查。

## 评估结果与历史汇总

已完成评估优先展示结果：单次模式展示一轮，对照模式并排展示两轮。问题、验收标准、条件及人工评审控件按需展开。人工评审保存后有明确反馈，Repeat 使用原输入创建新评估。

历史可按问题名称／正文、Agent 和创建日期筛选，截止日期包含本地时区当天。查看记录后返回 History，在同一工作台内保留筛选与页码。汇总覆盖所有匹配页面，并分别统计单次检查与双轮对照。单次正确率只纳入已完成、有查询、已评审且配置未变的采集；双轮对照要求两轮都满足这些条件。未评审、无查询和配置变更记录被排除。不同问题、模型及数据仍可能影响结果，不能据此自动宣称模型质量改善。

问题仍加密存储，搜索逐条解密，不新增明文索引，并受每源记录上限与 10 秒请求期限约束。筛选仅保存在当前页面内存，不写入浏览器地址或本地存储。
